# 2026-06-14 工作表功能对话复盘

本文把本轮围绕“工作表”功能的经验和教训沉淀到 EBAssistant 项目内，供后续开发直接参考。

## 最终实现

- 项目模板目录树已实现读取、缓存和刷新。
- 树节点默认折叠。
- 模板项目节点右键提供“新建工作表”。
- 新建工作表窗口支持导入 Excel、只读预览、AID 校验、最终名称预览。
- Excel 多页签批量创建工作表。
- 工作表固定创建为器件工作表。
- 保存位置固定为所选项目的 `工作表 / 收藏夹`。
- 创建后显示结果窗口，并保存 JSON/TXT 日志。
- 列标签编辑暂时跳过，Excel 第一行标签只用于预览、列宽计算和日志。

## 关键经验

1. 保存在哪个项目，就从哪个项目的设备目录创建。
   - 正确上下文是所选项目自己的 `EquipmentFolder`。
   - 不能从另一个普通项目创建后移动配置。
   - 不能从模板收藏夹配置对象本身直接打开工作表。

2. `工作表 / 收藏夹` 的定位应使用对象类型而不是中文名称猜测。
   - `Project.WorksheetTemplatesFolder` 定位“工作表”目录。
   - `AucObjectKind.aucObjFavoriteListConfigurations` 定位“收藏夹”。
   - 路径显示给用户时使用中文完整路径。

3. Excel 规则必须保持稳定。
   - 每个页签对应一个工作表。
   - 第一列忽略。
   - 第二列开始才是工作表列。
   - 第一行是标签预览。
   - 第二行是属性 ID。

4. 写入前要重新解析目标。
   - 缓存只用于快速展示目录树。
   - 真正创建前，适配器必须重新解析模板项目、收藏夹和已有工作表名称。
   - 最终名称以适配器返回为准。

5. 跳过项不能影响最终命名。
   - 校验失败的页签不会创建，也不能占用同名后缀。
   - 只有有效页签才参与批次内名称保留。

6. 日志是功能的一部分。
   - 用户需要知道哪些成功、哪些失败、哪些因为校验跳过。
   - 每次操作都保存 JSON 和 TXT。
   - 日志保存失败不应改变已经发生的 EB 写入结果。

## 关键教训

1. 不要把工作表配置对象当成工作表窗口。
   - 从收藏夹配置对象直接打开，会失败或显示“无可用于此对象的对象”。

2. 不要把 `aucCmdOpenSheet` 当成选择指定工作表配置。
   - 它可能只打开普通设备列表，右侧列头是“名称 / 注释”，不是目标工作表列。

3. 不要把 `OpenWorksheet(配置名称)` 当成交互打开。
   - SDK 语义里 string 参数应按配置对象 ID 理解。
   - 按名称返回 COM 对象不等于 EB UI 已切换到工作表。

4. 列标签编辑不能偷换成属性名称。
   - COM 公开成员没有可写列标签。
   - 交互命令未形成稳定无人值守方案前，正式功能必须明确“不写入列标签”。

5. 能力验证不要留下数据库残留。
   - 临时对象必须有明显前缀。
   - 创建、读回、删除、再读回要闭环。
   - 本次最终正式提交没有做真实 EB 写入，以免留下测试工作表。

6. 文档要跟最终代码状态同步。
   - 旧交接曾写“正式 CreateWorksheets 未实现”，现在已过时。
   - 后续如果需求改变，比如恢复列标签编辑，也要同步更新 `AGENTS.md`、设计文档和交接文档。

## 后续开发边界

- 正式产品路线优先使用强类型 COM。
- 主程序继续只做 UI、Excel、预览、日志和适配器调用。
- EB COM 继续隔离在 2023/2024 x86 适配器。
- 不使用 `dynamic`。
- 不使用固定坐标或盲目 `SendKeys`。
- 未经用户明确批准，不使用 SQL 内部表写入作为产品默认功能。
- 权限配置、图形模板、工具面板配置后续也应沿用“预览、校验、执行、读回、日志”的模式。
