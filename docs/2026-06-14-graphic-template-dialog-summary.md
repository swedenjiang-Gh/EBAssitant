# 2026-06-14 图形模板开发与排障复盘

本文记录本轮围绕 EBAssistant“图形模板”功能完成的开发、真实 EB 排障、最终实现边界和后续注意事项。内容以当前 `main` 分支最终状态为准。

## 最终实现

### 图形模板主窗口

- 主界面“图形模板”入口已从占位提示改为实际功能窗口。
- 左侧显示 EB 图形模板目录树，右侧显示所选目录中的模板图形并提供复选框。
- 初次无缓存时递归读取完整目录树并保存缓存。
- 存在缓存时直接加载缓存，不重新读取 EB。
- 点击“刷新”只浅层读取当前所选目录：
  - 更新当前目录中的模板图形。
  - 更新当前目录的直接子目录结构。
  - 保留其他目录缓存，不进行全树重读。

### 迁移模板图形

- 用户勾选右侧模板图形后，可打开“迁往目录”窗口。
- 迁往目录只允许选择最后一级目录。
- 模板图形允许重名，不以名称作为迁移前的唯一标识。
- 最终操作语义为复制，不删除源对象：
  - EB 命令使用 `aucCmdSymCopy` 和 `aucCmdSymPaste`。
  - 复制后通过目标目录新增对象 ID 读回确认。
  - 源对象始终保留。
- 操作完成后展示结果，并保存独立 JSON/TXT 日志。
- 日志目录：

  `%LOCALAPPDATA%\EBAssistant\Logs\GraphicTemplates`

### 类型不匹配确认框

EB 在部分复制场景会提示：

`图形符号类型与图形模板类型不匹配。单击“确定”转换图形符号类型。`

最终处理方式：

- 不隐藏 EB 主窗口。
- 不隐藏确认框。
- 仅识别上述白名单提示。
- 优先使用 Win32 `EnumWindows` 查找 EB 进程下的 `#32770` 对话框。
- 读取对话框子控件文字，确认提示内容匹配后点击“确定”。
- UI Automation 仅作为 fallback。
- 支持同一次批量操作中多次出现该确认框。
- 未识别的 EB 对话框不会自动点击。

### 按表格迁移

- 图形模板窗口新增“按表格迁移”按钮。
- 支持导入 `.xlsx` 和 `.xls`。
- 使用 `Templates/迁移模板图形模板.xlsx`：
  - A 列：序号，仅预览。
  - B 列：源目录相对路径。
  - C 列：模板图形名称。
  - D 列：目标目录相对路径。
- 目录路径不包含根目录“图形模版”，例如：

  `器件/仪表/传感器，流量`

- 导入只读取当前缓存，不重新读取 EB。
- 预览校验源目录、目标目录、末级目录状态及同名模板匹配数量。
- 模板图形允许重名；同名匹配数量大于 1 时标记错误，不静默选择。
- 当前“确定”按钮仅提示功能暂未开发，不执行实际迁移。

### 新建模板图形

- 图形模板窗口新增“新建模板图形”按钮。
- 点击时要求：
  - 已选择最后一级目录。
  - 所选目录中恰好存在一个模板图形。
- 条件不满足时提示：

  `需要选择最后一级目录，并且目录中只能存在一个模板图形。`

- 满足条件后输入最终总数量，范围为 `2-200`，总数量包含原有模板图形。
- adapter 在一次 EB 连接中：
  1. 对唯一模板执行一次复制。
  2. 向当前目录粘贴 `n-1` 次。
  3. 每次粘贴后轮询目录新增 ID，最多等待 5 秒。
  4. 通过唯一新增 ID 读回确认。
  5. 第一次失败后立即停止后续复制。
- 已成功创建的模板图形保留，不回滚、不删除。
- 完成后刷新当前目录缓存，展示结果并保存 JSON/TXT 日志。

## 图形模板目录和缓存

### 目录结构如何生成

图形模板根目录来自：

`app.Folders.Stencils`

完整读取时，adapter 按 EB 返回顺序递归枚举 `Children`：

- AID 45 有值：判断为模板图形，加入当前目录的 `Templates`。
- AID 45 无值：判断为目录，加入 `Children` 并继续递归。

每个目录缓存：

- `Id`
- `Name`
- `FullPath`
- `Kind`
- `TypeName`
- `Children`
- `Templates`

每个模板图形缓存：

- `Id`
- `Name`
- `FullPath`
- `ParentDirectoryId`
- `Kind`
- `TypeName`
- `SymbolSyncDesignation`
- `MasterUniRef`

### 缓存位置

`%LOCALAPPDATA%\EBAssistant\Cache\GraphicTemplates`

缓存按 EB 版本和图形模板根目录 ID 隔离。

缓存 JSON 中中文默认显示为 `\uXXXX`，这是 `System.Text.Json` 的转义结果，不代表中文丢失。程序反序列化后会正常还原中文。

### 已确认的目录 Kind

示例路径 `器件/仪表/传感器，流量`：

| 层级 | Kind |
| --- | --- |
| 器件 | `aucObjStencilsDevices` |
| 器件/仪表 | `aucObjStencilDeviceFolder` |
| 器件/仪表/传感器，流量 | `aucObjStencilDeviceType` |

整个图形模板树中，用于划分类型目录的 Kind 包括：

- `aucObjStencilFunctionType`
- `aucObjStencilLocationType`
- `aucObjStencilDeviceType`

本轮曾从缓存生成“整个图形模板目录，到 `aucObjStencil...Type` 为止”的临时清单。清单保存在系统临时目录，没有加入项目仓库。

## 重要问题与根因

### 确认框不自动点击

症状：

- 确认框仍在前台。
- 程序不会自动点击“确定”。
- adapter 长时间不退出并占用 EXE，导致新 adapter 无法编译覆盖。

根因：

- EB 确认框可通过 Win32 子控件稳定读取，但 UI Automation 不一定能找到顶层对话框。
- 旧实现以 UI Automation 找到窗口作为前置条件，导致 Win32 fallback 根本没有机会执行。
- 某些修复只改了源码，但正在运行的旧 adapter 占用输出 EXE，因此实际测试的仍是旧逻辑。

经验：

- 排查时必须同时确认源码、实际运行进程和输出 EXE 时间戳。
- 对 EB 原生模态框，Win32 窗口类、子控件文字和按钮句柄是更可靠的识别依据。
- 不要为了隐藏确认过程调用 `ShowWindow(handle, 0)`；这会造成 EB 主窗口或模态框状态混乱。

### 复制成功但日志记录失败

症状：

- 目标目录中已经出现模板图形。
- adapter 立即读回时未找到对象，日志记录失败。

根因：

- EB 粘贴命令返回与目录枚举可见之间可能存在延迟。

处理：

- 新建模板图形流程在每次粘贴后轮询新增 ID，最多等待 5 秒。
- 迁移流程仍应关注类似延迟，如果再次出现，应统一采用条件轮询而不是立即单次枚举。

### 源对象删除风险

早期迁移语义曾尝试“迁移后删除源对象”，真实 EB 测试发现目标创建和源删除之间可能出现不一致。

最终决策：

- 迁移模板图形改为复制语义。
- 不删除源对象。
- 日志状态使用 `copied`。

这样避免了“目标未确认成功但源对象已经删除”的数据风险。

### 跨大目录复制边界

真实 EB 操作层面不允许部分跨大目录复制粘贴。

当前边界：

- 程序调用 EB 已确认的复制/粘贴命令。
- 若 EB 不接受操作或无法读回，记录失败。
- 不尝试未经验证的底层类型转换。

未来可验证方向：

- 是否能在底层保留模板图形符号，同时把对象类型转换成目标目录可接受的类型。
- 此方向目前仅为假设，未实现、未确认。

## 开发与验证经验

1. 主程序和 adapter 协议必须同步。
   - `EbAdapterClient` operation 名称、主程序请求/响应模型、adapter DataContract 模型必须一致。

2. EB COM 逻辑继续只放在版本 adapter 中。
   - 主程序不直接引用 Aucotec COM。
   - 不使用 `dynamic`。

3. 写入后必须读回确认。
   - API 没有抛异常不等于写入已经可见。
   - 对 EB 异步可见行为，应使用条件轮询。

4. 批量写入必须明确失败策略。
   - 新建模板图形首次失败后停止。
   - 已成功创建的对象保留。
   - 结果和日志必须反映 `completed`、`partial` 或 `failed`。

5. 缓存刷新要限制范围。
   - 用户刷新一个目录时，只读该目录的浅层结构和模板图形。
   - 不应因为单目录刷新重新遍历整棵图形模板树。

6. 真实运行版本必须核对。
   - adapter 进程可能占用 EXE。
   - 修复后要确认进程退出，并确认 2023/2024 adapter 输出文件时间戳已经更新。

7. PowerShell 输出中文乱码不等于源码损坏。
   - 读取中文源码或 JSON 时应显式使用 UTF-8。
   - 修改后应通过 UTF-8 精确读取确认关键中文字符串仍存在。
