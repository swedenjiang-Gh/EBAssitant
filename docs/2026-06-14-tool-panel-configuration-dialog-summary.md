# 2026-06-14 工具面板配置与主菜单开发复盘

本文记录本轮围绕 EBAssistant“工具面板配置”、主菜单模板下载和日志入口完成的开发内容、最终实现规则、失败教训和后续维护边界。内容以提交 `ba6a28a Add tool panel configuration workflow` 后的实现为主要依据。

## 做了什么

### 工具面板配置入口

- 主界面“工具面板配置”入口已从占位提示改为实际功能窗口。
- 窗口分为三部分：
  - 左侧：图形模板目录树。
  - 中间：所选图形模板目录下的模板图形列表。
  - 右侧：`数据库 / 模板 / 工具面板配置` 下的目录和条目树。
- 左侧和中间区域复用图形模板目录结构和模板图形读取逻辑，不再为工具面板配置另做一套图形模板目录读取。
- 右侧工具面板树显示 `Kind 413 / 414 / 415` 节点。
- 只有右侧选中 `Kind 415` 条目时，“添加到工具面板”按钮才允许执行。
- 添加成功后展示结果窗口，写入 JSON/TXT 日志，并提示用户需要重启 EB 才能在 EB 界面中稳定看到配置变化。

### 图形模板与工具面板配置共用缓存

- 图形模板和工具面板配置共用同一套图形模板目录缓存。
- 第一次进入任一功能时，如果缓存存在就直接读取缓存。
- 如果缓存不存在，当前功能直接读取 EB 并生成缓存，不要求用户先打开另一个功能。
- 刷新逻辑保持“只刷新当前选择的目录”：
  - 左侧图形模板刷新只更新所选图形模板目录。
  - 右侧工具面板刷新只更新所选工具面板目录或条目。
  - 任一侧刷新都不应触发另一侧重新读取。

### 添加模板图形到工具面板

- 最终语义不是复制、粘贴、迁移，也不是新建工具面板条目。
- 正确操作是把中间区域选中的模板图形关联到右侧已选中的现有 `Kind 415` 条目。
- 实现边界：
  - 目标必须是已有 `Kind 415` 条目。
  - 不创建新的 `Kind 415` 条目。
  - 不移动或复制原始模板图形。
  - 写入后通过读回确认关联结果。
- 当前实现依据为 EB 数据库中的关联关系：工具面板 `Kind 415` 条目通过 `Role 132` 关联真实模板图形对象。

### 主菜单“下载模板”

- 文件菜单下的“下载模板”不再维护固定 Excel 文件名清单。
- 点击时扫描程序输出目录 `Templates` 下所有 `.xlsx` 和 `.xls` 文件。
- 只下载 Excel 表格，不下载 PDF、TXT 等非 Excel 文件。
- 因此后续只要把新的 Excel 模板放入项目 `Templates` 并由 csproj 复制到输出目录，就会自动进入下载范围。

### 主菜单“日志”

- 菜单栏新增“日志”入口。
- 点击后打开日志根目录：

  `%LOCALAPPDATA%\EBAssistant\Logs`

- 如果目录不存在，先创建再打开。
- 该入口打开总日志目录，不进入某个功能子目录，方便用户统一查找所有功能日志。

## 关键教训

### 1. “添加到工具面板”不能沿用图形模板迁移逻辑

本轮一开始曾把“添加模板图形到工具面板”理解成类似图形模板迁移或复制。这个方向是错的。

以后遇到工具面板配置时必须先区分：

- 图形模板迁移：目标是图形模板目录，语义是复制模板图形。
- 工具面板配置：目标是工具面板配置条目，语义是建立引用关联。

两者不能共用写入逻辑。

### 2. 右侧树必须显示 `Kind 415` 条目

右侧不是只显示目录。用户需要选中最后的工具面板配置条目，也就是 `Kind 415`，才能把模板图形关联进去。

如果右侧只显示目录，就会丢失真正的写入目标。

### 3. 不要新建 `Kind 415` 条目

另一个容易误判的方向是“每个模板图形创建一个 Kind 415 条目”。本轮用户明确纠正：实际需求是选中已有 `Kind 415`，把模板图形关联到它。

除非未来有明确需求和验证，不要在“添加到工具面板”流程里创建新的 `Kind 415` 对象。

### 4. 工具面板配置写入后要提示重启 EB

数据库写入后，EB 当前进程可能仍持有缓存。即使数据库读回确认成功，EB 界面也不一定立刻刷新出来。

所以成功提示和结果日志必须明确：添加成功后需要重启 EB。

### 5. 缓存语义要站在用户操作上理解

“直接调用图形模板的目录结构”不是指启动工具面板配置时强制重新读一遍图形模板目录，而是指：

- 和图形模板功能共用目录读取结果。
- 谁先读取都可以生成缓存。
- 谁后打开都应优先使用已有缓存。
- 用户点刷新时才重新读，并且只读当前选中的局部目录。

### 6. 模板下载应基于文件夹，不基于硬编码清单

固定文件名清单会导致新增 Excel 模板后忘记同步代码。当前更稳的规则是扫描 `Templates` 下所有 Excel 文件。

非 Excel 文件仍由对应菜单处理：

- 帮助手册：`docs/操作手册.md`
- 版本信息：根目录 `CHANGELOG.md`

### 7. 验证时注意主程序文件锁

如果 `EBAssistant.exe` 正在运行，构建或测试可能因为输出 EXE 被锁定而失败。

验证前可关闭当前 EBAssistant 主进程；验证后如果用户需要继续操作，再重新打开主界面。

## 后续维护建议

1. 继续保持主程序与 EB COM/数据库写入隔离，主程序只走 adapter JSON 协议。
2. 工具面板配置后续扩展前，先确认目标对象是目录、`Kind 415` 条目，还是模板图形引用关系。
3. 对工具面板配置写入，不要做“自动删除、批量清理、自动重建”之类高风险操作。
4. 新增模板文件时优先放入 `Templates`，Excel 会自动进入“下载模板”，非 Excel 由专门菜单或文档入口处理。
5. 新增功能日志时继续写入 `%LOCALAPPDATA%\EBAssistant\Logs\<功能名>`，这样主菜单“日志”能统一打开根目录。
