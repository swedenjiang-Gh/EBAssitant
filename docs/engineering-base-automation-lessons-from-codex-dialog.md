# EB2023 自动化经验与教训

本文沉淀本次 Codex 对话中已经执行、观察或验证的 Engineering Base 2023 自动化经验，供 EBAssistant 后续设计、实现和验证使用。

## 1. 运行环境与版本边界

- EB2023 COM ProgID 为 `EngineeringBase.Application.30`。
- 本机 EB2023 可执行文件路径为 `C:\Program Files (x86)\Aucotec\Engineering Base 720\bin\EngineeringBase.exe`。
- 本次操作使用 SQL Server 实例 `.\EB140`、数据库 `EB1_2023`。
- EB2023 为 32 位 COM 应用。自动化程序和诊断脚本应优先使用 x86 适配器或 32 位 Windows PowerShell；64 位进程可能因 COM 位数不匹配得到 `MK_E_UNAVAILABLE`。
- EBAssistant 正式代码应继续使用版本化、强类型的 x86 适配器。临时诊断脚本中观察到的隐藏命令或数据库结构，不应直接变成默认产品能力。

## 2. 对象定位与路径消歧

- EB 中同名对象很常见。任何写入操作都必须同时校验数据库、项目、完整父路径、对象类型和对象 ID，不能只按名称命中第一个结果。
- 数据库系统节点的 SQL `Designation` 可能是 `@9...` 资源编码；面向用户的中文显示名称应从 EB COM 对象读取。
- SQL OID 可转换为常见 EB ID 形式：`00000000-0000-0000-0000-{OID.ToString("X12")}`。该转换可用于诊断和交叉校验，不能替代对象类型与父路径验证。
- 查询、预览和执行阶段都应记录目标 ID。执行前重新解析目标，发现零个或多个候选时立即中止。

## 3. 图形模板与 Visio 符号编辑器

- 已观察到可用于图形模板打开诊断的命令：
  - `57119 OpenShape`
  - `57180 SymOpenMaster`
  - `57189 SymOpen`
- `SymOpenMaster` 或 `SymOpen` 可打开 Visio 图形符号编辑器。应通过窗口标题和目标对象再次确认，例如 `图形符号编辑器 (设计模式) - Visio Professional`。
- 当符号编辑器已打开时，重复发起打开命令可能阻塞。执行前应检查现有编辑器窗口和未处理对话框。
- Visio 不一定注册到 Running Object Table。必要时通过进程、窗口标题和子窗口枚举确认状态。
- 出现“是否保存修改”等保存或放弃对话框时，程序不得替用户决定，必须暂停并请求用户选择。

已确认的对象定位样本：

| EB 路径 | 对象 | OID | EB ID 尾部 | Kind |
|---|---:|---:|---|---:|
| `图形模板/器件/常规/端接` | 文件夹 | `3857117` | - | - |
| `图形模板/器件/常规/端接` | `A` | `3857118` | `3ADADE` | `93` |
| `图形模板/器件/管道/三通/CGN` | `CGN` 文件夹 | `4093817` | - | - |
| `图形模板/器件/管道/三通/CGN` | `1` | `4093818` | `3E777A` | `204` |

`管道` OID 为 `115024`，`三通` OID 为 `2956048`。这些 ID 仅作为当前数据库样本证据，产品功能必须在运行时重新解析。

## 4. 工作表列标签编辑实测

本次目标为项目 `test` 下的工作表配置 `测试工作表`，工作表配置 OID 为 `4102540`，EB ID 为 `00000000-0000-0000-0000-0000003E998C`。

Excel 中的目标列标签依次为：

1. `名称1`
2. `演示属性`
3. `A`

目标配置下三个列记录均为 `CID=19`，按 `Order` 排序：

| 列记录 OID | Order | 原标签 | 最终标签 |
|---:|---:|---|---|
| `4297614` | `80` | `311` | `名称1` |
| `4297615` | `112` | `3111` | `演示属性` |
| `4297616` | `144` | `A` | `A` |

关键观察：

- `GetSnglObjectByID` 能解析工作表配置，但对这三个 `CID=19` 列记录返回空。
- 从父级收藏夹调用 `OpenWorksheet("测试工作表")` 能返回 Worksheet，但本次样本的 `Worksheet.Columns.Count` 为 `0`。
- 因此，不能假设现有工作表的内部列记录始终能通过普通 `ObjectItem` 或 `Worksheet.Columns` 编辑。
- 本次通过精确限定 `OIDParent=4102540`、`CID=19` 和列记录 OID，在 SQL 事务中更新 `dbo.[Object].Designation`，随后逐条读回确认成功。
- `dbo.[Object]` 存在触发器，`ExecuteNonQuery` 返回值会包含触发器影响行数。验证精确更新数量时应使用 `SELECT @@ROWCOUNT`，并在同一事务中完成更新、读回和失败回滚。

这条 SQL 路线只能作为受控诊断或人工批准的修复路线，不能作为 EBAssistant 正式功能的默认实现。正式产品路线仍应优先验证：

`IAucVbaInternUtils.ExecuteCommand(AucCommand.aucCmdEditColumnLabel, sourceObject)`

若采用 EB 原生编辑命令，必须通过 UI Automation 唯一定位工作表窗口、列标题和“编辑列标签”对话框；未知对话框或定位歧义必须中止。

## 5. 工作表列宽

- SDK 中 `WorksheetColumn.Width` 可写，不代表标签在真实 EB 界面中一定完整显示。
- 自动列宽完成后，应使用较长中文标签做一次可见性验证，例如 `演示属性`。
- 列宽写入失败或读回不一致时，应把当前工作表记录为失败，不能仅记录“命令已执行”。

## 6. 属性、类型定义与图形模板操作

- 属性创建、删除和改名都必须限定属性根目录或完整子目录路径，并在执行前检查重名和引用关系。
- 类型定义对话框中的“移动属性”和“重命名选项卡”是两个独立操作，必须分别验证。属性移动成功不代表选项卡改名成功；本次对话中已出现该类静默失败。
- 图形模板的复制、移动、改名和删除应保留原始顺序与精确对象 ID。批量操作前提供预览，批量删除必须再次确认目标目录和对象清单。
- 遇到“图形符号类型与图形模板类型不匹配”提示时，只能处理已识别、已白名单化的提示；未知提示立即中止。
- 从外部 Visio 文件复制图形时，应等待文件完全打开，按组合块坐标排序，确认剪贴板内容，并显式处理关闭时的保存提示。

## 7. UI 自动化安全规则

- 正式功能不得依赖固定屏幕坐标或盲目 `SendKeys`。
- 优先使用强类型 EB COM API；确需 UI 自动化时，使用唯一窗口、控件层级、标题和状态进行定位。
- 仅自动处理已识别且业务含义明确的提示。未知对话框、多个候选窗口、焦点不确定或超时均应中止并记录诊断信息。
- 不得自动回答保存或放弃修改的问题。
- 每次操作结束后检查残留对话框和编辑器窗口，避免影响下一次任务。

## 8. EBAssistant 设计反馈

- 将“受支持的 EB COM/UI 路线”与“受控数据库诊断修复路线”明确分层；后者默认禁用，并要求人工批准、事务、精确目标、读回和审计日志。
- Excel 导入应保持只读预览优先，展示最终目标路径、列顺序、列标签、属性 ID、冲突和将执行的操作，用户确认后再写入。
- 适配器操作应返回结构化结果，包括 EB 版本、数据库、项目、完整路径、目标 ID、执行路线、每步状态、读回结果和错误信息。
- 缓存必须按 EB 版本和数据库身份隔离。执行写入前重新解析目标，不能直接信任缓存对象。
- 版本能力必须独立验证。EB2023 中确认的隐藏命令、对象 Kind 或内部表结构，不能自动推断为 EB2024 可用。
- 对创建、复制、移动、改名和删除操作，结果窗口与日志应能显示成功、跳过、失败、回滚和残留对象检查结果。

## 9. 工作表列标签功能验收标准

1. 按数据库、项目和完整路径唯一定位工作表配置。
2. 验证 Excel 标签数与目标列数一致，并按稳定列顺序映射。
3. 零候选、多候选、列数不一致或窗口定位歧义时不执行写入。
4. 使用受支持路线编辑后逐列读回标签；无法读回时明确标记为未验证。
5. UI 路线结束后没有残留对话框，且不自动处理保存或放弃提示。
6. 记录执行路线、目标配置 ID、每列目标 ID、原值、新值、状态和日志路径。
7. 诊断 SQL 路线仅在人工明确批准后启用，并强制事务、`@@ROWCOUNT`、读回和失败回滚。

## 10. 实施优先级

1. 首先验证 `aucCmdEditColumnLabel` 的稳定调用对象、窗口定位和读回方式。
2. 将列标签编辑能力作为版本化适配器操作，返回结构化逐列结果。
3. 增加长中文标签列宽验证和真实界面可见性检查。
4. 保留 SQL 实测结论作为排障知识，不把内部表更新接入默认批量创建流程。

## 11. 工作表创建专项最新结论

工作表配置保存在哪个项目，就必须从同一个项目的“设备”目录打开和修改。正确目标路径为：

```text
项目模板 / 所选模板项目 / 工作表 / 收藏夹
```

不得使用另一个普通项目作为交互上下文，也不得创建后跨项目移动配置。

SDK 文档说明 `OpenWorksheet(string, ...)` 的 string 参数是工作表配置对象 ID，不是显示名称。已确认按配置名称非交互打开不会把 EB UI 切换到真正工作表窗口；按配置名称交互打开在 EB2023 报 `COMException：该对象不允许使用方法!`。因此正式创建流程不依赖 `OpenWorksheet(...)` 交互打开路径。

当前 EBAssistant 正式 `CreateWorksheets` 路径已经改为：

1. 解析所选项目。
2. 用所选项目自己的 `EquipmentFolder.OpenWorksheetDirect(...)` 创建器件工作表。
3. 添加属性列并设置列宽。
4. 调用 `Worksheet.SaveConfiguration(name, favoriteFolder)` 直接保存到同一项目的 `工作表 / 收藏夹`。
5. 从收藏夹读回确认。

自定义列标签编辑已按用户要求暂时跳过。Excel 第一行标签只用于预览、列宽计算和日志；正式功能不调用 `aucCmdEditColumnLabel`，也不使用 UI Automation 或 SQL 内部表写入。

## 12. 2026-06-14 列标签实施方式回溯

用户回问“测试工作表列标签当时是怎样实施的”时，重新核对了 EngineeringBaseCodemap 中的运行证据、KR 和 OOE 卡片。结论是：2026-06-13 那次成功修改不是通过 EB 的“编辑列标签”对话框，也不是通过 `Worksheet.Columns` 写入，而是一次受控的数据库内部列记录修复。

当时的完整实施链路如下：

1. 用 Excel COM 读取 `D:\工作资料\鹰达信科\上海鹰达\AI+设计\EB CodeMap测试\工作表.xlsx` 的 `Sheet1` 第一行。
2. 得到目标列标签顺序：`名称1`、`演示属性`、`A`。
3. 在 EB2023 数据库 `.\EB140 / EB1_2023` 中按 `Designation='测试工作表'` 查找工作表配置对象。
4. 发现存在两个同名对象：项目 `测试项目` 下 OID `4102500`，项目 `test` 下 OID `4102540`。
5. 通过 SQL 父链确认目标必须是项目 `test` 下的 OID `4102540`，EB ID 为 `00000000-0000-0000-0000-0000003E998C`。
6. 读取 `OIDParent=4102540 AND CID=19` 的直接子记录，并按 `OrderNumber, OID` 排序。
7. 将 Excel 标签依次映射到三个内部列记录：

| 列记录 OID | OrderNumber | 原标签 | 新标签 |
|---:|---:|---|---|
| `4297614` | `80` | `311` | `名称1` |
| `4297615` | `112` | `3111` | `演示属性` |
| `4297616` | `144` | `A` | `A` |

8. 在 SQL transaction 中按 exact OID 更新 `dbo.[Object].Designation`。
9. 每条更新后使用 `SELECT @@ROWCOUNT` 验证只命中一行，不依赖 `ExecuteNonQuery()` 的返回值，因为 EB 数据库触发器可能放大受影响行数。
10. 提交后再次按 `OIDParent=4102540 AND CID=19` 回读，确认顺序和值为 `名称1`、`演示属性`、`A`。

当时也验证了两条看起来更自然的路线不可用：

- `GetSnglObjectByID` 能解析工作表配置对象 `4102540`，但不能把 `4297614`、`4297615`、`4297616` 解析为普通 `ObjectItem`。
- `parent.OpenWorksheet("测试工作表")` 能返回 `Worksheet`，但该样本中 `Worksheet.Columns.Count=0`，所以不能通过 `Worksheet.Columns` 找到可写列标签对象。

对 EBAssistant 的后续开发教训：

- 这条路线只能作为“人工明确批准的诊断修复路线”，不能接入默认批量创建或无人值守适配器。
- 如果未来要实现正式列标签编辑，应优先重新验证 EB 原生命令 `aucCmdEditColumnLabel=57515`，并用 UI Automation 精确定位窗口、列标题和对话框。
- 同名工作表必须通过项目父链消歧；名称、路径、OID、CID、列数和读回值都要同时进入日志。
- 对任何数据库内部写入，都必须使用事务、精确 OID、`@@ROWCOUNT`、提交后读回，以及失败回滚。
- 这次经验不能泛化为“工作表创建时可写自定义列标签”。当前产品设计中，自定义列标签仍应按已确认边界处理：若未完成原生命令实测，就只用于预览、列宽计算和日志。
